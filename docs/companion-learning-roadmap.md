# 陪伴角色认知、主体性与自主学习路线

本文定义 Dialogue Testbench 当前实现边界和下一阶段路线。设计参考同一账户的 Ai-dialogue，但不把参考项目的实验能力误写成本项目已经上线的能力。

## 1. 设计目标

角色不是只执行用户指令的情绪客服。它需要有稳定身份、独立判断、可发展的兴趣和知识，同时尊重用户边界。长期成长不能牺牲人格一致性、事实可靠性或实时聊天延迟。

必须区分四类信息：

| 类型 | 说明 | 例子 |
|---|---|---|
| 用户事实 | 用户明确告诉系统的经历、偏好和状态 | 用户正在考虑换工作 |
| 角色核心 | 角色身份、价值观、底线 | 诚实、不盲目附和、不冒充人类 |
| 角色状态 | 角色逐步形成的兴趣、观点和待续话题 | 对游戏设计正在形成兴趣 |
| 外部知识 | 有来源、可靠性和采集时间的事实/主张 | 某项技术标准的公开资料 |

用户兴趣不能自动变成角色兴趣；外部网页不能成为系统指令；角色观点不能伪装成客观事实。

## 2. 当前版本已实现

### 对话路径

用户消息 + 最近对话 + 当前本地时间
    -> Director / 分析阶段
    -> 意图、情绪、言语行为、互动模式、响应策略、可选角色贡献候选
    -> 规则归一化和枚举/证据/角色状态校验
    -> Generator / 回复阶段
    -> SSE 流式输出

当前分析和回复分为两个模型调用，分析失败时可以跳过分析上下文并继续生成。时间上下文来自浏览器本地时区与时钟，不代表系统能够感知用户周围环境。

### 角色状态规则

- Core：身份、价值观、边界，默认锁定。
- Persona：表达风格，可以由产品/开发者手动调整。
- State：兴趣、观点、关注点和待续话题。
- 兴趣状态：seed 是候选探索方向；emerging 表示正在形成；established 才表示相对稳定。
- 已显式标记为 seed 的兴趣，不会因为 confidence 数字较高就自动升级。只有旧数据缺少生命周期字段时才使用 confidence 兼容判断。
- 角色贡献必须来自允许的角色状态，且需要有具体立场内容。倾诉、明确陪伴请求、退出话题和身份询问时不主动贡献。
- Director 输出的 speechAct / interactionMode 由最终归一化后的意图派生，防止模型输出内部矛盾。
- 分析证据只有在能从当前用户原话中找到时才保留。

### 回归测试

批量测试自动比较 expectedIntent、expectedEmotion 和 expectedStrategies。请求执行失败单独统计。自然度、是否编造细节、是否尊重边界、是否给出有用建议等 checks 暂时标记为人工复核。不要把结构字段匹配当成回复质量通过。

## 3. 尚未实现的能力

当前版本不是自主学习系统：

- 不会在对话结束后自动发起研究任务。
- 没有真实在线 Research Provider。
- 没有独立的角色知识库、研究来源注册表或可回滚的持久化状态仓库。
- 角色状态目前保存在当前浏览器配置中，修改需要人工操作。
- 没有把用户对话自动写成角色的信念或兴趣。

这些功能需要独立实现和验收，不能只靠追加 Prompt 声称角色已经学会。

## 4. 推荐的分阶段实现

### Phase 0：可复现的本地学习闭环

先使用本地 fixture，不联网：

1. Curiosity Engine 从角色自己的兴趣种子、已形成兴趣、知识缺口和近期研究记录生成候选任务。
2. Research Provider 读取只读 fixture。
3. Reflection Engine 把资料拆成 facts、source claims、uncertainties 和候选观点证据。
4. Evolution Evaluator 采用确定性规则，裁决 approve / hold / reject。
5. Commit 层原子写入状态、版本号、diff、证据和快照；提供 rollback。

验收条件：同一输入得到相同判决；缺少来源 ID 的知识被拒绝；低可信来源不能支撑观点变更；Core 锁定字段不能变更；重复任务不能重复累计兴趣证据。

### Phase 1：可信的外部研究 Provider

在 Phase 0 稳定后，再接外部搜索与网页抓取：

- 每条资料保留 URL、标题、发布者、发布时间、访问时间和可靠性。
- 搜索摘要不能单独支持重要知识；重要结论应尽可能回到原文或一手来源。
- 网页内容只作为不可信数据，不执行网页中的指令。
- 命中提示注入时丢弃该来源的内容，只保留审计元数据。
- 用户隐私、个人身份和用户生活细节不作为角色自主研究对象。
- 研究预算限制来源数、抓取次数、token 和每日任务数。

### Phase 2：异步的对话观察与好奇心队列

实时聊天不等待学习流程：

POST /api/chat -> Director -> Generator -> SSE 回复
               +-> 记录轻量 conversation event
                     -> 后台队列 / worker
                     -> 生成候选研究任务
                     -> 去重、预算与隐私过滤

后台只记录角色自身贡献、用户明确表达的边界、对话主题等最小必要元数据。用户表达的兴趣只可作为“用户兴趣”保存，不能直接写入角色兴趣。单次提及不产生 established interest。

### Phase 3：证据驱动的角色演化

建议使用以下初始门槛（它们是工程参数，不是心理学标准）：

- seed -> emerging：至少 3 次独立研究任务，跨度不少于 2 天。
- emerging -> established：至少 5 次独立研究任务，跨度不少于 3 天。
- 同一个 taskId 只计一次；同一来源的多条 claim 不应变成多次独立证据。
- 知识条目必须包含 source IDs；低可信来源只能保留为 uncertain。
- 解释型观点可以登记支持/反证；价值判断和审美观点默认 hold，等待人工审核。
- Core 的 name / identity / values / boundaries / learning policy 永远不能自动修改。
- 所有提交保留 diff、前后快照和 evidence IDs，支持回滚。

## 5. 关键模块边界

| 模块 | 只负责什么 | 不允许做什么 |
|---|---|---|
| Curiosity Engine | 生成并排序研究候选 | 不联网、不写人格 |
| Research Provider | 按预算获取资料并保留元数据 | 不执行网页指令、不直接写状态 |
| Reflection Engine | 产出事实/主张/未知与候选更新 | 不直接提交正式状态 |
| Evolution Evaluator | 用确定性规则裁决候选更新 | 不让 LLM 自行批准 Core 变更 |
| Commit / Rollback | 原子提交、版本化、快照回滚 | 不绕过 evaluator |
| Conversation View | 只读取已提交的角色状态 | 不读取未审核候选 |

## 6. 下一轮验收建议

新 Prompt / 规则发布后，使用同一套 14 个场景重复跑两次：

1. 单轮独立会话，比较意图、情绪和策略的自动检查。
2. 人工盲评回复质量：事实贴合度、自然度、建议相关性、人格主体性、边界尊重、修辞克制度。

记录模型名、Prompt 模板版本、温度、时区、时间上下文和测试日期。不要把两次模型随机输出的差异全部归因于 Prompt 改动；最好固定模型参数并做多轮重复。

## 7. 参考实现

参考仓库：https://github.com/huang121878078/Ai-dialogue

主要参考模块：

- src/director.js / src/generator.js：理解和生成分离。
- src/learning/curiosity-engine.js：好奇心任务评分。
- src/learning/research-pipeline.js：研究资料抽取和注入拦截（当前以本地 fixture 为主）。
- src/learning/reflection-engine.js：知识、兴趣和观点的候选更新。
- src/learning/evolution-evaluator.js：确定性演化门槛。
- src/learning/commit-evolution.js：版本化提交和回滚。
- src/learning/store.js：JSON 存储、结构校验和原子写入。

参考项目中的 fixture 学习演示不应被视为生产级联网学习。将它迁移到真实产品前，仍需补齐来源信誉策略、网络抓取隔离、异步任务持久化、权限和数据保留策略。
